# Document previews

DOCX attachments open as paginated PDF previews generated by LibreOfficeKit on
the server. The original DOCX stays unchanged and the Download button always
returns it. This handles automatic pagination, table flow, section layouts,
headers, footers, images and fields through an office layout engine instead of
approximating them with HTML. The preview does not edit the document.

This is not Microsoft Word: unsupported features and unavailable proprietary
fonts can still differ. The image includes Liberation, Carlito, Caladea and
DejaVu fonts. Use an author-exported PDF when exact Word output is required.

Both server images include the renderer. Native Linux server installations need
`python3`, `libreoffice-writer`, `libseccomp2` and the fonts above. Page previews
require Linux 6.2+ with Landlock ABI 3 enabled (including the Linux host behind
Docker). No extra container privileges or relaxed seccomp settings are needed.
Older kernels, older servers or missing dependencies use the existing local
HTML quick preview with an explicit layout notice.

Each conversion uses a new private directory and office profile. Macros are
disabled; Landlock restricts filesystem access and, where supported, scopes signals/abstract Unix
sockets. Seccomp blocks all network sockets, signals to other processes, process
creation and process-memory access. Only the conversion directory is writable.
The process exits after each render, with a 75-second deadline, CPU/address-space
and file-size limits. At most one conversion runs across the server; another
request falls back to quick preview. No document or preview is cached or sent
to an outside service. Temporary files are removed after conversion.

Local validation: `python3 deploy/test-render-document.py` and
`node tools/frontend/test-document-pages.cjs` (also with `WEBKIT=1`). Use only
synthetic reports in committed tests; customer reports must remain outside Git.
